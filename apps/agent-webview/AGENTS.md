# Agent Webview 前端约定

本文件补充根目录 `AGENTS.md`，适用于 `apps/agent-webview`。Webview 是任务交互和状态展示边界，不持有服务端工作流状态。

## 组件与目录

- React 组件遵循“一文件一组件”：每个 `.tsx` 文件只定义一个 React 组件，文件名与组件名一致；页面、阶段和可复用子组件均需拆分，Props 类型和非组件辅助类型可以与所属组件同文件维护。
- 前端组件、页面状态和展示模型按业务功能组织在 `src/features`；所有面向 Agent Server 或宿主能力的业务数据源统一放在 `src/data-sources/<domain>`，按独立业务领域拆分契约与实现。领域内部只有在出现独立变化、复用、测试或替换边界时，才继续按阶段或能力建立子目录，不因方法数量机械拆分，也不建立跨领域的万能文件或 Service。应用入口、依赖组装、主题挂载和顶层路由统一放在 `src/app`；只有被多个功能复用且不包含业务语义的内容才进入 `shared`。

## 技术与样式

- Webview 使用 React 和 Ant Design；功能组件的新增或修改样式默认使用 CSS Modules，避免功能样式泄漏到其他页面。
- `src/styles.css` 只维护 reset、全局 Token 和应用壳层样式。确需由同一功能内多个组件共享普通 CSS 时，可以保留一个功能级样式表，但所有选择器必须位于稳定的功能根类命名空间内，不使用 `.main-panel`、`.content` 等无作用域的通用类名。
- Webview 使用 Vite 和 TypeScript Bundler 模块解析，因此本目录覆盖根目录的 NodeNext 导入约定：TypeScript、TSX 模块的相对导入省略文件扩展名，样式等非 TypeScript 资源保留扩展名。
- 优先通过 Ant Design `ConfigProvider`、全局 Token 和组件 Token 适配设计。
- 只有主题和业务组件无法覆盖时，才增加页面布局或局部样式。
- 不依赖 Ant Design 内部 DOM 层级、哈希类名或大量 `!important`。

## 状态管理

- 不要求所有组件机械拆分状态层与视图层。请求、轮询、命令执行、复杂状态转换，以及需要独立测试或跨组件复用的状态逻辑，可以提取到功能级 Hook 或 Controller；简单且只服务于单个组件的 UI 状态应与视图就近维护，避免无实际收益的透传组件和 Hook。
- 导出的自定义 Hook 必须添加有意义的文档注释，说明职责、关键参数、返回能力，以及请求、轮询、订阅、清理等重要副作用和停止条件；私有且简单的 Hook 可以依靠清晰命名表达用途，不为明显的状态字段、Setter 或逐行实现添加重复注释。
- 状态按最小共享范围就近维护：被多个子组件或阶段共同使用的状态由最近的公共父组件维护，只服务于单个子组件的状态保留在该子组件内部，不为统一管理而无条件提升状态。
- 独立、局部且更新方式简单的状态使用 `useState`，例如输入值、弹窗开关、展开项和视图切换；不能仅因为状态字段较多就改用 `useReducer`。
- D2C 设计读取和 SVG 生成状态以 Agent Server 返回的版本化快照为唯一事实来源；Webview 不使用本地 Reducer 或定时器模拟服务端状态转换。
- 新建任务完成当前用户操作后可以继续既定流程；从持久化 taskId 路由恢复任务时只读取快照，不得在挂载 Effect 中自动启动分析、代码生成、写入或验收，必须显示显式继续操作。
- 仅属于当前页面且不需要在页面刷新或客户端重连后恢复的复杂交互状态，在确有状态机约束时才使用 `useReducer`，并集中定义 Action、Reducer 和状态转换测试。
- 能从 Props 或现有状态直接计算出的值保持为派生值，不使用额外的 `useState` 或 Effect 重复同步。

## 数据边界

- Webview 的 `src/communication` 维护环境无关的 `CommunicationClient` 调用接口，以及 VS Code、Web HTTP 等可替换传输实现；应用组合层只注入一次由当前宿主环境选定的 `CommunicationClient`，不逐项登记业务请求或数据源。`src/data-sources/<domain>` 在各自领域入口将通用通信适配为强类型数据源，功能组件只消费已校验的抽象业务方法和领域事件，不直接调用 `CommunicationClient`、`acquireVsCodeApi` 或 HTTP。
- 正式源码不内置 Mock、演示任务或固定业务结果；生产数据通过明确的数据源接口注入，并在进入组件前完成运行时校验。
- Fixture 统一放在 `fixtures/`，只能由开发入口和测试引用；生产入口、正式组件和生产构建不得导入或包含 Fixture，开发入口与生产入口必须显式分离。

## 状态展示

- UI 只展示当前已实现的设计输入、SVG 生成、项目检查、组件判断、审阅型方案、Plan 生成与写入授权、真实命令独立授权、受控 Patch 应用、构建、页面渲染和视觉门禁结果，以及真实错误和按任务所有权读取的执行证据。命令必须展示 `cwd`、`executable`、`argv` 和哈希；目录外计划不得渲染自动批准入口。反馈修订和自动修复等未实现阶段不得用静态假数据占位成可用功能。
