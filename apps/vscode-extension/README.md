# ui-forge for VS Code

在目标项目中输入设计链接、图片和需求，由 Codex 完成 React + TypeScript 页面的实现、审查和验证。

## 安装与连接

1. 在 VS Code 扩展面板的更多菜单中选择 **Install from VSIX…**，安装 `ui-forge-<版本>.vsix`。
2. 在与 VSIX 同版本的 ui-forge 仓库根目录运行 `npm run ui-forge -- serve`，保持该终端运行。源码构建需要 Node.js 22.12+ 和 VS Code 1.105 或更高版本；后端需要已登录的 Codex CLI 和构建后的 ui-forge 服务。
3. 在 VS Code 用户设置中搜索 `ui-forge.serverUrl`，填写后端地址，默认 `http://127.0.0.1:4310`。端口与后端的 `UI_FORGE_PORT` 保持一致；修改后重新加载窗口。
4. 在当前 VS Code 窗口中打开并信任要生成代码的目标项目，点击活动栏的 ui-forge 图标，再点击 **+** 创建任务。

插件包含任务页面，Agent Server 需单独运行。当前连接本机 HTTP 服务，项目路径和结果文件均由本机访问。

```json
{
  "ui-forge.serverUrl": "http://127.0.0.1:4310"
}
```

## 设计与验收

设计来源和图片限制见根目录 [README](../../README.md#设计来源)，严格像素验收的启用方式和前置条件见 [配置与验收](../../README.md#配置与验收)。插件页面可以同时接收设计链接、图片和需求；新建任务时勾选“严格像素验收”即可启用，缺少原图或 Python/Pillow 时仍可继续功能实现，但验收项会受阻或未验证。

任务进行中可补充文字或图片、回答问题、处理审批或停止本轮。关闭页面只断开查看，停止后端会结束其 Codex 进程。查看历史不自动开始新一轮；继续修改需回到任务对应的工作区。

发送、停止和回复前会核对返回历史的任务 ID 与当前工作区目录；授权检查完成后、转发前再次确认目录与信任状态未变化。不一致时拒绝该请求，不自动重试，也不会改用另一任务的历史授权。诊断、交付查询和历史浏览不会因此获得执行权限。

## 连接问题

- 无法连接：确认后端已启动、端口一致，再刷新历史。修改设置后需重新加载窗口。
- 无法创建或继续任务：确认当前窗口已打开并信任任务的目标项目。
- 后端提示登录或配置不可用：在后端终端运行 `npm run ui-forge -- doctor`，再按 [Codex 接入说明的配置与检查](../../packages/codex-client/README.md#配置与检查) 完成 ui-forge 包项目的信任和 D2C 配置检查。

截图、审查和验收结论以实际工具输出为准；本轮结束不等于验收通过。
