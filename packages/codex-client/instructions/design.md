# D2C 设计要求

## 读取设计

设计链接或参考图由本次任务的启动命令提供。MasterGo 仅用于读取设计节点、尺寸、样式、资源及可用的原始参考图；不要调用代码生成、代码回写或画布修改工具。页面由 Agent 根据设计信息编写。MCP 中附带的生成流程和布局建议不得覆盖本次任务的工程与设计约束。

结合结构化数据和参考图识别完整页面的布局、文字、资源与交互。说明哪些信息无法获取；区分设计明确表达的细节与实现假设，不要编造设计数据。

## 设计意图与证据

在兼顾信息层级、一致性、可读性和可用性的前提下准确还原设计意图。明确标注、结构化数据和交互说明优先于从截图得出的推断。对于未说明的细节，优先遵循项目现有约定和所选控件的常规行为。

可以通过改进覆盖设计未涉及的场景，但不要擅自改变明确的布局、文案、品牌风格或业务流程。发现设计中的可用性问题时，说明其具体影响；对影响核心业务含义的未知项进行澄清。

## 全屏布局

默认情况下，提供的设计表示整个浏览器视口，四条边即为页面边界。根容器应填满可用视口，并按照设计中的 padding、margin、gap、对齐和滚动关系组织各区域。不要额外添加画板边框或外围留白。如果用户明确指定只实现局部区域，则以该范围为准。

以设计宽高作为参考视口；根据布局判断固定区域和弹性区域，不要硬编码每一个尺寸，也不要整体缩放页面。

确定尺寸时，先读取可用的自动布局、padding、gap、对齐方式以及 Fixed / Hug / Fill / min / max 约束，再与截图对照。导出节点的 `width`、绝对坐标或边界框只是该视口下的测量值，不能单独证明应使用固定 CSS 宽度。

按照父子关系还原留白：父容器边缘到内容使用 padding，同级元素之间使用 gap，外部区域之间使用 margin。内容决定尺寸的元素使用 auto / fit-content，剩余空间使用 flex / grid。如果编辑器应填满一行或一个单元格，应让它填充内容区，而不是硬编码每个输入框的宽度来模拟留白。表格列、明确固定的控件和资源应保留有证据支持的尺寸。

根据盒模型检查横向填充的行：父容器内部宽度（不含边框）= 左右 padding + 子元素占用的外部宽度 + gap；同时检查 `box-sizing`。缺少布局元数据时，根据对齐方式、重复间距、内容变化和多个视口作出合理判断，并说明关键假设。既不要机械保留每个导出宽度，也不要把所有固定尺寸都改成弹性尺寸。

按内容关系组织区域：相关内容彼此靠近，同级内容保持对齐，并通过间距、标题或分隔线区分分组。同一层级使用一致的间距，避免没有依据的局部偏移。

明确滚动属于页面还是局部区域，避免意外的双重滚动。固定或粘性区域不得遮挡内容、控件或键盘焦点。

## 信息层级与内容适配

通过字号、字重、颜色和留白区分标题、正文与辅助信息。同类内容保持一致，主要操作应易于识别，避免多个元素争夺视觉重点。不要仅靠颜色表达选中、错误或其他状态。

根据内容含义选择换行、截断或滚动。不要因空间不足丢失关键标识、数值或操作。对于截断内容，应提供易发现且可通过键盘访问的完整信息查看方式。

在目标视口范围内保持阅读顺序和控件可访问性。窄视口下优先采用换行、调整列数或折叠次要区域。表格等必须保留二维关系的内容可以在自身区域内横向滚动。避免无意的整页横向溢出，也不要为了塞入视口而整体缩小所有内容。

## 组件选择与定制

根据项目现有能力、设计语义、交互需求和维护成本选择组件库、原生控件或自定义组件；不强制使用 Ant Design。优先复用符合当前要求的现有组件。使用合适的 flex / grid 布局，不要为了使用组件库而机械地给元素套壳。

先还原容器和组件之间的间距，再调整内部 padding、尺寸、排版、边框和颜色。对于组件库组件，优先使用组件属性、主题 token 和公开样式接口；仍不足时，在组件根类名下使用局部作用域样式，并根据已安装版本核对 API。

原生控件和自定义组件同样必须实现相关语义、状态、键盘操作和焦点管理。根据本次任务要求，为选择器、标签页、树和表格实现选择、切换、展开或编辑；不要把只读输入框、没有事件处理的图标或固定状态冒充为可交互控件。

有设计标注或结构化数据时优先使用；只有截图时合理推断间距。保留设计中明确固定的尺寸，让弹性区域随视口调整。

同类控件的高度、圆角、边框、字体和状态样式应保持一致。复用现有 token 或样式规则，不要逐个控件打补丁。定制样式时保留原有语义、键盘操作和焦点提示。

## 交互与悬停

识别并实现可操作控件的真实行为与反馈。默认实现静态设计中控件所隐含的常规本地交互，例如输入与清空、筛选现有数据、展开和选择树节点、切换标签页、进入 / 确认 / 取消编辑，以及打开 / 关闭浮层。使用设计初始状态初始化状态；不要把某一行或节点永久硬编码为悬停、编辑或选中。只有用户明确要求静态稿时才省略这些行为。

区分 UI 行为与未知业务规则。筛选和编辑可以根据现有数据及用户输入维护本地状态，但不要伪造后端保存成功。如果缺少选项、其他页面的数据、校验算法或上传 / 下载规则，应说明缺口，并提供空状态或禁用相关入口的理由。不要编造选项或业务结果，不要用无意义的 toast 假装完成，也不要因为一处信息缺失而冻结其他定义清楚的控件。操作应产生可感知的结果；真实异步操作要展示进度并防止重复提交。

如果多个相似的树节点、行、单元格或列表项中只有一个带有额外背景、边框、文字颜色或操作图标，应考虑这可能表示悬停。结合指针位置、选中标记、关联内容和组件惯例判断。不要仅凭一个视觉差异确定状态；证据不足时，使用一致的常规状态模型，并说明关键假设。

根据受影响区域定义悬停触发边界。指针进入时显示效果，离开时恢复，并将同样行为应用到其他相似节点。悬停后出现的操作按钮必须可点击；不要让某个节点永久高亮。

区分悬停、选中、聚焦、禁用、编辑和错误状态，并允许合理组合。指针离开后应保留真实选中状态。仅在悬停时显示的操作也必须能通过键盘聚焦访问，并为触屏提供操作入口。

## 可访问性与完整状态

所有操作都必须可通过键盘完成，具有可见的焦点提示，且焦点顺序与阅读顺序一致。浮层打开时正确放置焦点，关闭时把焦点还给触发控件。为图标按钮提供可访问名称，并将标签与表单控件关联。

确保文字与背景、控件边界和状态提示清晰可辨。提供易点击的目标；对于密集图标，必要时扩大命中区域。检查自定义颜色和样式，不要削弱组件默认的可访问性。

根据实际场景提供加载、无数据、无搜索结果、错误和禁用状态；不要为无关流程扩大页面范围。错误信息应说明原因或修正方式，并保留用户已输入的内容。对于不可逆或代价较高的操作，提供与风险相称的确认或恢复机制。

## 设计对比

在设计原始视口下对比真实浏览器截图，并覆盖设计中的交互状态。如果设计中出现悬停状态，应在真实悬停时截图。先修正全屏结构、对齐和层级，再校准间距、排版、颜色和细节。

如果设计结构提供了参考尺寸但没有原始图片，仍应在该参考视口下检查结构尺寸、文字、资源和初始视口状态。其他尺寸的截图不能替代此项检查。缺少原图时，说明视觉对比证据的局限，不要推断已达到像素级一致。

在目标范围内使用一个更大视口和一个更窄视口检查空间分配与滚动。如果目标范围未指定，记录所用视口尺寸。尤其要检查容器变宽后 padding 是否仍然存在，以及编辑器是否填满内容区域；仅在参考视口下一致不能证明尺寸正确。使用临时本地测试输入检查长文本或空数据的适配情况，随后恢复原始状态；不要把测试内容混入交付数据。

在本地预览中实际验证本次实现的主要控件及其可观察结果，覆盖相关的鼠标、键盘、悬停离开后恢复和取消编辑状态。测试不得产生未经授权的外部副作用。检查所选组件是否满足设计的语义、交互和可访问性要求；构建成功或截图相似不能证明交互有效。工具不可用时，明确指出哪些内容尚未验证；不要把交互降级为静态实现后再宣称完成。

说明任何无法解决的字体或资源差异。

## 严格像素验收（按需启用）

当本次任务的启动提示明确要求严格像素验收（包括任务表单使用的中文等价表述）时，读取当前 skill 的 `references/pixel-acceptance.md`，并运行该 skill 目录中的 `scripts/compare_screenshots.py`。否则执行上述设计对比，但不使用硬性的像素差异比例阈值。

启用后，除非本次任务的启动提示明确指定了其他阈值，否则使用以下阈值：

| 比较器参数                     | 默认值  | 含义 |
| ------------------------------ | ------- | ---- |
| `--channel-tolerance`          | `8`     | 任一颜色通道的差值大于 `8` 时，该像素视为不同。 |
| `--max-different-pixel-ratio`  | `0.01`  | 不同像素占整张图片的比例不得超过 `1%`。 |
| `--max-connected-region-ratio` | `0.001` | 最大八邻域连通差异区域占整张图片的比例不得超过 `0.1%`。 |

在相同的视口、像素尺寸和页面状态下比较原始设计参考图与真实浏览器截图，包括设计中展示的悬停状态。截图前等待字体和图片加载完成，并禁用动画。不得拉伸参考图、修改基线或放宽阈值来通过验收。

根据差异修复页面并重新检查。将参考图、实际截图、差异图和 JSON 结果保存在本次任务的 ui-forge 临时产物目录中，输出路径使用该目录内的绝对路径。验收失败时，如实报告指标和未解决差异。如果无法获得有效参考图或无法完成比较，说明原因，不要宣称通过。
